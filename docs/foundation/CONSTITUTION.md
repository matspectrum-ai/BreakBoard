# BreakBoard Constitution

## BB-CON-001 — Repository is context
All material product behavior and engineering decisions must exist in the repository. Conversation history is non-canonical.

## BB-CON-002 — Specification before implementation
No behavior may be implemented before it is specified sufficiently to test.

## BB-CON-003 — Tests before implementation
When implementation is unlocked, behavioral tests must be written fail-first before production implementation.

## BB-CON-004 — No silent invention
Agents expose missing requirements as open questions rather than invent behavior.

## BB-CON-005 — Determinism
Gameplay resolution is deterministic given the same state, action, and seeded randomness context.

## BB-CON-006 — Composition over volume
Depth should derive from interactions among composable primitives rather than large quantities of bespoke assets or special cases.

## BB-CON-007 — AI-buildable production
Core gameplay must not require high-volume manual sprites, 3D models, rigging, or frame-by-frame animation.

## BB-CON-008 — Explicit uncertainty
Hypotheses, balance parameters, open questions, and canonical decisions must be distinguishable.

## BB-CON-009 — Traceability
Canonical requirements must ultimately map to contracts, verification, and implementation.

## BB-CON-010 — Reversible planning
Premature technology choices are forbidden when requirements do not justify them.
